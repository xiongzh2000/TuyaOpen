一、背景与分析目标

当前 AI 打印机 Demo 的图像生成依赖外部生图 API，规模化量产前需要回答一个关键问题：如果向云厂商订购 A10 机器自建集群、部署开源 Flux.2-Keltin-4B 模型替代外采 API，单图成本与规模化经济性如何？

核心问题

  • 一台 A10 GPU 机器每天能产出多少张图？
  • 单张图的云资源成本是多少？
  • 一台机器可以支撑多少个终端设备？不同规模下总成本怎么走？
  • 相比外采云厂商的文生图 API（两个候选：z-image-turbo / multimodal-dialog），自建集群的盈亏平衡点在哪里？
结论速览：自建单图成本 0.10 分，单机可支撑 ~6,000 台设备；但因阿里 multimodal-dialog API 折后仅 ¥0.009/张，自建盈亏点从 z-image-turbo 的千台级上升到万台级——API 选型比"是否自建"更关键。

  • "两周热度"规律：公开行业访谈指出，AI 陪伴玩具样机前 2 周用户活跃度高，第 3 周起大量用户停用。平均使用频率呈现"先高后低"曲线。
  • 退货率 30~40%：AI 毛绒玩具行业媒体数据，部分用户"尝鲜"后即退货或闲置。
  • 留存率：头部厂商次月/三月留存"百分之大几十"，复购率 20%+；私域精细运营下月活留存最高 68%。

五、计算推导过程（公式透明）

以下全部推导基于阿里云主推方案（包 3 年预留 ¥1,762/月）。每一步公式都已展开，TL 可独立代入自己的参数重算。

① 日有效产能

# 24 小时计费 × 吞吐 × 利用率 日产能 = 24h × 3600s × 1 img/s × η = 86,400 × 70% = 60,480 张 / 天

② 单机日成本

# 24h 常开，月成本按 30 天均摊 日成本 = ¥1,762 / 30 = ¥58.73 / 天

③ 单图成本

单图成本 = 日成本 / 日产能 = ¥58.73 / 60,480 张 = ¥0.000971 / 张 ≈ 0.10 分

④ 单机可支撑设备数

设备数 = 日产能 / 单设备日用量 = 60,480 / 10 = 6,048 台 ≈ 6,000 台

⑤ 单设备全生命周期云成本

全周期用量 = 10 张/天 × 180 天 = 1,800 张/台 全周期自建成本 = ¥0.000971 × 1,800 = ¥1.75 / 台

⑥ 90 天短生命周期场景

短生命周期用量 = 10 张/天 × 90 天 = 900 张/台 90 天自建成本 = ¥0.000971 × 900 = ¥0.87 / 台 90 天 API 成本（multimodal-dialog） = 900 × ¥0.009 = ¥8.10 / 台 90 天 API 成本（z-image-turbo） = 900 × ¥0.075 = ¥67.50 / 台
关于 70% 利用率的说明：并非 GPU 吃不满 70%，而是从"实际可用产能"角度——预留 15% 给请求波动（国内高峰 + 海外时区不完全均匀）、10% 给冷启动/健康检查/模型重载、5% 给队列等待与维护窗口。如果能做到更精细的批量调度与预热，η 可拉升到 80~85%，单机设备数最多可到 ~7,340 台。

决策区间建议

任何规模
优先评估 multimodal-dialog
折后仅 ¥0.009/张，是自建的 9.3 倍，但免运维、免算法、免基础设施。前提是生图质量能满足 AI 打印机产品要求——这是最需要优先验证的事情。
质量不达标时
z-image-turbo + 自建 POC
若 multimodal-dialog 质量不够用 z-image-turbo：< 1,400 台外采、1,400~1 万台启动自建 POC、> 1 万台全面自建。可混合部署降低风险。
> 12,000 台
全面自建（对 multimodal-dialog）
规模超过 1.2 万台，自建对即使便宜的 multimodal-dialog 也开始具备经济性。但此阶段应考虑多 SKU/多模型路线，用最贵的场景跑自建。
非成本维度的考量：自部署还需要承担——模型迭代（Flux 系列更新后需要重新调优）、GPU 供应（A10 阶段性紧张）、合规出海（海外数据不落地要求）、多地域冗余（故障容灾）等复杂度。规模 < 1 万台时，这些隐性成本通常比 GPU 本身还贵；而 multimodal-dialog 由云厂商承担所有这些复杂度。

八、结论与建议

API 选型比"是否自建"影响更大
外采 multimodal-dialog（¥0.009/张）比 z-image-turbo（¥0.075/张）便宜 8.3 倍，差距甚至超过"z-image-turbo vs 自建"的差距。先评估便宜的 API 是否能满足产品质量要求，是第一性问题。
单台 A10 可覆盖 ~6,000 台终端设备
按每台设备日均 10 张、24 小时服务、70% 利用率估算。即便到 10 万台规模，也只需 17 台 A10，月 GPU 成本 ≈ ¥3.0 万。
阿里云 gn7i 包 3 年是国内最优解
月成本 ¥1,762，比 AWS g5 3 年预留低 17%。出海业务再单独用 AWS，就近部署降低延迟。
分情景的决策路径
情景 1：multimodal-dialog 质量达标 → 规模 < 12,000 台都继续外采，省心省人力。情景 2：必须用 z-image-turbo → < 1,400 台外采、1,400~10,000 台混合 POC、> 10,000 台全面自建。
下一步行动建议
① 立即用 multimodal-dialog 做样品生图，对比 z-image-turbo 与 Flux.2-Keltin-4B 的质量差距（成本差 8 倍，质量差距是核心决策依据）；② 跟阿里商务确认 multimodal-dialog 的 7.5 折实际合同价与 SLA；③ 实测 Flux.2-Keltin-4B 在 A10 上的真实吞吐，校验 1s/张假设；④ 基于行业调研数据（10 张/天 × 180 天）建立用户使用量的长期监测。

附录：未计入的成本与风险

未计入的直接成本

  • 公网带宽：10Mbps 约 ¥200/月；图片返回若走公网，规模化后可达 ¥2,000+/月
  • 云存储 ESSD：¥0.3~0.6/GB/月，相册缓存需按需测算
  • 模型文件存储：Flux.2-Keltin-4B 权重 ~8GB，可忽略
  • 监控 / 日志 / 告警：云厂商托管服务 ~¥500/月

未计入的间接成本

  • 运维人力（至少 0.5 HC SRE，月 ~¥15,000）
  • 算法团队对推理服务的持续支持（模型版本升级、prompt 工程）
  • 多区域部署的管理开销（国内 + 海外双活）
  • GPU 紧张期的替代成本（A10 不可得时可能需要用 L20/A100 临时方案）

风险提示

  • 吞吐假设待验证：1 img/s 基于 512×512 4-step 蒸馏版推测，实测可能 0.8~1.2，影响 ±20% 产能
  • 利用率 η 敏感：如真实 η = 50%，单机设备数降至 4,320 台，规模成本上升 40%
  • 设备生命周期假设风险：180 天是当前基准；若实际只有 90 天，满载摊销下自建成本约 ¥0.87/台，multimodal-dialog 约 ¥8.10/台，z-image-turbo 约 ¥67.50/台，但短生命周期也意味着产品留存不足；若留存更长（如 270/365 天），自建优势加大
  • multimodal-dialog 质量风险：价格便宜 8 倍的背后，需要评估生图质量是否匹配打印机输出要求，这是采购决策的最大不确定因素
  • 模型迭代：Flux 系列若升级到更大参数量，A10 24GB 可能无法承载，需升级到 A100
  • 云厂商长合约锁定风险：包 3 年可节省大量成本，但若业务规模不达预期，提前退租违约金较高
